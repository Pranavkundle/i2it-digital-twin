What this prototype demonstrates

M1In this demo

3D Campus Viewer

Three buildings rendered as stacked floor slabs in Three.js, standing in for the Blender-exported models in the full system.

M2In this demo

Building & Floor Navigation

Click a building to see its floors separate out, then click a floor to open its room list.

M3In this demo

Search Module

Keyword search across room names and IDs, jumping the viewer straight to the matching floor and room.

M4Simulated

AI Query Module

Pattern-matching over the local dataset answers "where is…" and "how many floors…" questions — a stand-in for the NLU layer in the proposal.

M5Not in this demo

Database & Admin Module

Room data here is a hard-coded JavaScript object. The real system replaces this with the MongoDB schema and REST API from the architecture diagram.

M6In this demo

Floor Plan Viewer

The "Floor plan" toggle swaps the 3D view for a lightweight 2D room grid, as the fallback module describes.

This is a front-end prototype built for Project Review – II. Building geometry, floor counts and room names below are representative sample data, not a real floor survey — Phase 1 of the project timeline (requirement & data collection) is what would replace them with actual room lists for the Academic Building, PPCRC and Library. The room ID scheme (Building–Floor–Room, e.g. B001-F02-R01) matches the one in the proposal. Live indoor positioning is explicitly out of scope for v1, per the proposal's scope boundary, and is not attempted here.
